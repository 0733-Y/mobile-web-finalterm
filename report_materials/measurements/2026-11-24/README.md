### count 모드 1건의 이유
- 처음 30프레임 동안 0명으로 안정 → 프레임 38(1.27초)에 `0명` 업로드.
- 이후의 인원 변화는 모두 마지막 업로드 후 60초가 지나기 전(영상 끝 61.87초)에 일어나 업로드되지 않음.
- 오프라인 시뮬레이션(아래 2와 같은 프레임별 인원 수로 같은 규칙을 계산, `summary_none.json`)도 같은 결과(1건, 프레임 38)여서 실제 실행과 일치.
- 참고(시뮬레이션, 실제 업로드 아님): 최소 간격을 0초로 하고 30프레임 안정 조건만 두면 12건.

## 2. YOLO 프레임별 사람 수의 안정성 (`measure_input.py`, `per_frame_none.csv`, `summary_none.json`)
- 사람 수 분포: 0명 1196프레임, 1명 649프레임, 2명 11프레임 (영상 속 실제 최대 인원은 학생 확인 필요. 2명 11프레임이 실제인지 중복 검출인지 미확인)
- 직전 프레임과 인원이 달라진 횟수: **33회**
- 같은 인원이 이어진 구간: 34개, 그중 **30프레임(1초) 미만인 구간 22개**, 가장 긴 구간 307프레임
- baseline 실행(80클래스)에서도 person 이 있는 프레임은 660개로, person 만 검출한 측정(649+11=660)과 같음.
- 해석: 프레임 단위 인원 수는 1초 미만으로 바뀌었다 돌아오는 경우가 많아서(22구간), "0→1 즉시 업로드"는 이 흔들림을 그대로 Post 로 만든다. 30프레임 안정 조건은 33번의 변화를 12번의 변화 이벤트로 줄였다(시뮬레이션).

## 3. F1 블러 전후 얼굴 수 (`per_frame_yunet.csv`, `summary_yunet.json`)
- 검출기: OpenCV `cv2.FaceDetectorYN` (YuNet, `face_detection_yunet_2023mar.onnx`, opencv_zoo, 232,589 바이트), score 임계값 0.9 (예제 기본값, 조정하지 않음). 영상 1856프레임 전부 검사.
- 영상 속 인물은 마스크를 착용함 → 원본에서도 얼굴 검출이 적음.

| | 얼굴 검출 수(합계) | 얼굴이 검출된 프레임 |
|---|---|---|
| 블러 전 (원본) | 59 | 59 |
| 블러 후 (`blur_boxes`) | **0** | **0** |

- 사람이 검출된 프레임은 660개인데 원본에서 얼굴이 검출된 프레임은 59개뿐 → 이 검출기로는 마스크 쓴 얼굴을 대부분 못 찾음. 따라서 "블러 후 0"은 "검출기가 찾을 수 있던 59건이 모두 사라졌다"는 뜻이지, 모든 프레임에서 얼굴이 가려졌다는 증명은 아님.
- 얼굴이 검출됐는데 사람이 검출되지 않은 프레임: 0 (블러가 빠지는 경우 미관찰).
- 같은 측정의 사람 수 통계는 2절과 동일 (0명 1196 / 1명 649 / 2명 11, 변화 33회).
